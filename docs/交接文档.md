## 1. 这是什么

.NET 8 模块化单体（ADNC 风格）。一个进程 `NXAI.Host`，多模块、多 `DbContext`、同一 MySQL 库 `nxai`。

员工管后台。会员是壶的主人。Asset 管 SN。Device 管在线仓位和 MQTT。Recipe 管模板。Cooking 管这一壶。Inventory 管手里的耗材。Catalog 是货架。AfterSales 管工单。

**商品 ≠ 耗材 ≠ 仓位 ≠ 配方 ≠ 任务。实物 SN ≠ 在线会话。**

V1 明确不做：AI、支付订单、Recommend、组合料盒、推送中台、称重闭环、真机联调、TDengine / EMQX 集群。  
空项目 `Brain` / `Agent` / `Integration` 不要用。以后做管理端 Agent，走 ACL 调现有 Application 服务，禁止直发 MQTT、禁止绕过 Cooking。

## 3. 怎么跑

依赖：.NET 8 SDK、MySQL 8.0（`127.0.0.1:3306` / 库 `nxai` / `root`/`root`）、EMQX、RabbitMQ。

```bash
docker compose -f deploy/emqx/docker-compose.yml up -d
docker compose -f deploy/rabbitmq/docker-compose.yml up -d
dotnet run --project src/Hosts/NXAI.Host
```

| 服务 | 地址 | 账号 |
|---|---|---|
| Host / Swagger | http://localhost:5100/swagger | 切 console / portal / device / internal 四份文档 |
| EMQX MQTT | 1883 | 本地 compose **关了监听器认证**，模拟器可直接连 |
| EMQX Dashboard | http://127.0.0.1:18083 | admin / public |
| RabbitMQ AMQP | 5672 | guest / guest |
| RabbitMQ 管理台 | http://127.0.0.1:15672 | guest / guest |

配置：`src/Hosts/NXAI.Host/appsettings*.json` 与 `appsettings.shared.Development.json`。Development 会加载后者。

建表：各模块 `*SchemaHostedService` 启动时 `EnsureCreated`。同一库已被别的模块建过时，再 `CreateTables` 补本模块缺表。**没有 EF Migration。** 改实体后旧库可能对不上，开发库可删库重建。

RabbitMQ 没起来时 Host / CAP 会起不来或一直重连。设备指令**不走** RabbitMQ。

NuGet：偶发 nuget.org EOF。包已在本机 `%USERPROFILE%\.nuget\packages` 时可用该缓存还原。不要升 CAP 到 8.4（会拉 Microsoft.Extensions 9，和本仓库 8.x 钉死冲突）。现状：`DotNetCore.CAP 8.3.3` + `RabbitMQ.Client 7.0.0`。

## 4. 鉴权（先搞清楚再调接口）

| 端 | 前缀 | Token | 怎么拿 |
|---|---|---|---|
| 后台 | `/api/console` | JWT `token_type=staff`，`aud=console` | 开发：`POST /api/internal/dev/staff-session`。正式：`POST /api/console/auth/session`（System `sys_user`） |
| 小程序 | `/api/portal` | JWT `token_type=member`，`aud=portal` | `POST /api/portal/auth/session`，短信开发环境固定 `000000` |
| 设备 HTTP | `/api/device` | `X-Device-Token` | `POST /api/device/activate` |
| 调试 | `/api/internal` | 仅 Development | 员工会话、模拟器辅助上报 |

表面隔离：`ApiSurfaceTokenMiddleware`。员工 Token 打 portal、会员 Token 打 console → 403。`sys_user.Id` 禁止写入任何 `MemberId`。

权限：`DeferredPermissionHandler` 目前恒 true。带 `AdncAuthorize` 的菜单权限还没接到 Redis。

会员会话：`mb_member` 上的 ValidationVersion（JTI 轮换），内存/库字段，**没接 Redis**。

## 6. 联调备忘

**员工 Token**

```http
POST /api/internal/dev/staff-session
```

**会员登录**

```http
POST /api/portal/auth/session
{ "mobile": "13800000000", "code": "000000" }
```

**模拟器**

```bash
dotnet run --project src/Tools/NXAI.PotSimulator -- --sn POT20260001 --local-temp 80 --mode happy
```

| 参数 | 含义 |
|---|---|
| `--mode happy` | 正常 SUCCESS |
| `--mode missing` | DISPENSE → MISSING（不扣库存） |
| `--local-temp` | 本地探头。低于 Trigger 温度则 DISPENSE 失败 |
| `--broker` / `--port` | 默认 127.0.0.1:1883 |

设备登录协议（EMQX 以后打开认证时）：`clientId=pot-{sn}`，`username=sn`，`password=deviceToken`。HTTP 回调已实现：`POST /api/device/mqtt-auth`。本地 compose 把 `ENABLE_AUTHN=false`，模拟器目前可不带 Token。

MQTT topic：`pot/{sn}/down/command`，上行 `pot/{sn}/up/ack|shadow|...`。只有 Device 连 EMQX。小程序不直连 Broker，看影子即可。

**水温开火**：只认硬件本地探头。禁止用影子/遥测 ≥80℃ 下发无 Trigger 的立即投放。Cooking 必须 HEAT SUCCESS 之后才发带 `TEMP_GTE` 的 DISPENSE。

## 7. 规格 vs 代码（接手必看）

这些不是「没写文档」，是代码有意或暂时没跟上规格。下一步不要当已经做完。

| 规格 | 代码现状 |
|---|---|
| 模块间一律 CAP 事件（[04-集成事件](rd/04-集成事件.md)） | **真正走 RabbitMQ 的只有 3 条**：`pot.device.command.acked.v1`、`pot.cooking.task.completed.v1`、`pot.cooking.task.failed.v1`（failed 无订阅，缺料不扣）。绑定、开维修、仓位投影等仍是单体里直接调对方 Contracts |
| 订阅方放 `Acl/` + `Subscribers/`，禁止 Application 直引对方服务 | Cooking / AfterSales 的 Service **直接注入**了 `IRecipeService` / `IDeviceService` / `IInventoryService` / `IAssetSnService`。要补 Gateway |
| 消费用 `IMessageTracker` 幂等 | 未接 |
| Redis 两套会话 | 未接。员工开发 Token 不查 `sys_user`；会员用库字段 JTI |
| 事件类型继承 `EventEntity<T>` | 当前是普通 DTO + `Topic` 常量，发布必须带主题名，不要用 `typeof(T).Name` |
| EMQX HTTP 认证 | 接口在，Broker 本地关认证 |
| 员工权限菜单 | `DeferredPermissionHandler` 全放行 |
| EF 迁移 | 无，只有启动建表 |

CAP 注册：`AddCapEventBus`。后续模块再调时仍会挂上自己的 `ICapSubscribe`（已修过「只有第一个模块订阅生效」）。发布用 `IEventPublisher.PublishAsync(topic, payload)`。

## 9. 建议的下一步（按优先级）

1. **工作区**：大量 V1 文件可能还没提交。先 `git status`，确认再推。不要把 `appsettings` 里的生产密钥提交上去（当前是开发占位）。
2. **亲手跑通主链路**（第 5 节），用模拟器 `happy` / `missing` 各走一遍。
3. **补防腐层**：Cooking / AfterSales / Inventory 把跨模块调用收进 `Acl/IXxxGateway`，为以后拆服务和接 Agent 留口。
4. **事件**：要不要把 [04-集成事件](rd/04-集成事件.md) 剩余主题从「同步 ACL」迁到 CAP。迁之前先定幂等（`IMessageTracker`）。设备指令继续 MQTT。
5. **库表**：用迁移替换 `EnsureCreated`，否则多人/多环境会漂。
6. **EMQX**：联调稳定后打开 HTTP 认证，模拟器带上 `deviceToken`。
7. **会话**：规格要 Redis；现在可以继续开发库字段，但上多实例前必须改。
8. **测试**：目前几乎只有 Pot 信封单测。主链路至少补 Cooking ACK / 扣库存 / 维修拒绑。
9. **二期**：Recommend / 管理端 Agent——只 ACL 查询与 `ICookingService.CreateAsync`，不能发 MQTT。

## 10. 红线（全局，抄自架构总览）

1. A 的 DbContext 出现 B 的实体。
2. Device 以外的模块发 MQTT。
3. 小程序 Token 打通 console，或员工 Token 打通 portal。
4. `sys_user.Id` 写入 `MemberId`。
5. 未出库 SN 绑定成功。
6. 配方步骤写死仓位号（只写 TargetCode）。
7. 茶包拆开按内部克数分别投。
8. `DISPENSE` 失败后换新 `commandId` 再投。
9. 影子/遥测 ≥80℃ 就下发无 Trigger 的立即投放。
10. 绕过 `ITelemetryStore` 写遥测。
11. 一壶两个 Running 任务，或上一步未 ACK 就发下一步投放。

写 C#：标识符英文，XML/`//` 用中文。DTO、Controller、实体必须有 `/// <summary>`，否则 Swagger 只剩类型名。见 `.cursor/rules/csharp-conventions.mdc`。

## 11. 已知坑

- 同一 MySQL 多 `DbContext`：`EnsureCreated` 只对「库还不存在」为 true；后到的模块靠 `CreateTables`。表已存在但缺列时**不会**自动改。
- CAP 8.3.3 官方依赖 RabbitMQ.Client 6；仓库是 Client 7（自定义 ConnectionManager 用了 async API）。CAP 走的是 CAP.RabbitMQ 适配器。若连 Broker 运行时异常，先查这两套 Client 是否打架。
- 雪花 `IdGenerater`：各模块 Registrar 里 `SetWorkerId(1)`，单机开发够用，多实例要重新分配 WorkerId。
- MQTTnet 钉在 `4.3.7.1207`，不要随便升 5。
- Host 不装 Recommend。System 仍是原后台，员工菜单/用户/角色可用，但业务接口开发期权限未校验。
)

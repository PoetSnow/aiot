# 架构总览

写任何模块前看完本页。细节在各模块文件里。

## 已拍板

| 项 | 结论 |
|---|---|
| C 端账号 | 独立 `NXAI.Member`，不复用 `sys_user` |
| 配方版本 | 方案 A：`Code+Version` 多行，发布后该版只读 |
| MQTT | 自建 EMQX 5 开源单节点，开发也用它 |
| 遥测 | 时序点模型 + `ITelemetryStore`；V1 用 MySQL，以后换 TSDB |
| 操作时序 | 一壶一任务、一任务一条在途指令；设备认 `epoch+stepNo` |
| 水温开火 | 只认硬件本地探头，不认影子/遥测曲线 |
| AI | 第一版不做 |

## 产品一句话

员工管后台。会员是壶的主人。Asset 管 SN。AfterSales 管工单。Device 管在线仓位和 MQTT。Recipe 管模板。Cooking 管这一壶。Inventory 管手里的耗材。Catalog 是耗材货架。AI 二期再接。

商品 ≠ 耗材 ≠ 仓位 ≠ 配方 ≠ 任务。实物 SN ≠ 在线会话。

## 长在现有 NXAI 上

- 新业务只加 `src/Modules/NXAI.{Name}/`，抄 `NXAI.System` 四层：API / Application.Contracts / Application / Repository。
- 不要用解决方案里空的 Brain / Agent / Integration。
- 单体入口：`src/Hosts/NXAI.Host`，`AddNXAIApplicationModules` 装模块。
- 每模块自己的 `DbContext` + 表前缀。禁止跨模块 `DbSet`。
- 模块 Application **只许**引用对方 `Application.Contracts`，且必须包在自己的 `Acl/`。
- 拆微服务：Contracts 不动，DI 换成 Refit。

```text
src/Modules/NXAI.{Context}/
  *.API                         Controller，只依赖本模块 Contracts
  *.Application.Contracts       接口、DTO、集成事件
  *.Application
      Acl/                      调别人只走这里
      Subscribers/              消费事件
  *.Repository                  本上下文实体，不引用其他业务模块
```

## 三端切开

| 端 | 路由 | Controller 基类 | 鉴权 |
|---|---|---|---|
| 后台 | `/api/console` | `ConsoleApiController` | 员工 JWT，`token_type=staff` |
| 小程序 | `/api/portal` | `PortalApiController` | 会员 JWT，`token_type=member` |
| 设备 HTTP | `/api/device` | `DeviceApiController` | `X-Device-Token` |
| 调试 | `/api/internal` | `InternalApiController` | 仅 Development |

投放走 MQTT，不走 `api/device`。Swagger 四份文档，互不混。详见 [03-API与Swagger](03-API与Swagger.md)。

## 进程与中间件

```text
NXAI.Host（一个进程）
  System / Member / Asset / AfterSales
  Device（唯一连 EMQX） / Recipe / Cooking / Inventory / Catalog
  不装 Recommend

MySQL   业务表 + 影子 + V1 遥测表
Redis   两套会话
RabbitMQ + CAP   模块间事件（不是设备指令）
EMQX    只给壶 / 模拟器
```

## 防腐层（所有模块同一套）

```text
Acl/IXxxGateway + XxxGateway
入参出参 = 本上下文类型
对方 DTO 变化只改 Gateway
```

Cooking 下发指令也走 `IDeviceGateway`。**只有 Device 引用 MQTT 客户端。**

Gateway 清单见各模块「ACL」节，总表见 [04-集成事件](04-集成事件.md)。

## 软件 / 硬件

| 能力 | 软件 | 硬件 |
|---|---|---|
| 何时投 | 下发带 Trigger 的单条指令 + 超时看门狗 | 本地探头到条件后才动作 |
| 投什么 | 解析到 slotCode | 操作该仓 |
| 投多少 | 下发 amount | 称重 / 整包 / 计数 |
| 温度展示 | 影子 + 遥测点 | 采集 |
| 投料开火 | 禁止用影子判定 | 再读一次本地水温 |

## 红线（全局）

1. A 的 DbContext 出现 B 的实体。
2. Device 以外的模块发 MQTT。
3. 小程序 Token 打通 console，或员工 Token 打通 portal。
4. `sys_user.Id` 写入 `MemberId` 字段。
5. 未出库 SN 绑定成功。
6. 配方步骤写死仓位号。
7. 茶包拆开按内部克数分别投。
8. `DISPENSE` 失败后换新 `commandId` 再投。
9. 影子/遥测 ≥80℃ 就下发无 Trigger 的立即投放。
10. 绕过 `ITelemetryStore` 写遥测。
11. 一壶两个 Running 任务，或上一步未 ACK 就发下一步投放。

# 开工顺序

按依赖做，不要按页面一次铺开。每做完一行，用「验收」勾掉再往下。

主链路：

```text
后台入库 SN → 出库 → 小程序登录 → 绑定 → 放耗材 → 选配方 → 启动任务
→ MQTT → 模拟器 ACK → 完成 → 耗材账本 -1
```

| 序 | 做什么 | 只读这些文档 | 验收 |
|---|---|---|---|
| 1 | `NXAI.Host` + 各模块空壳（可先建要做的模块项目） | [00-架构总览](00-架构总览.md)、[03-API与Swagger](03-API与Swagger.md) | Swagger 能切「后台 / 小程序 / 设备端」 |
| 2 | Member 登录 + 确认 System 员工登录互打不通 | [modules/member](modules/member.md)、[modules/system](modules/system.md) | 两套 Token 不能互访对方前缀 |
| 3 | `NXAI.Shared.Pot` 枚举 + MQTT 信封 | [02-共享内核](02-共享内核.md)、[protocol/mqtt](protocol/mqtt.md) | 信封能序列化 |
| 4 | Asset：型号、仓库、入出库、SN | [modules/asset](modules/asset.md) | 后台能入库/出库，库存按 SN 汇总 |
| 5 | Device：绑定、仓位、影子、Outbox | [modules/device](modules/device.md) | 未出库 SN 绑定失败 |
| 6 | EMQX + 模拟器 | [infra/emqx](infra/emqx.md)、[protocol/mqtt](protocol/mqtt.md)、[protocol/operation-order](protocol/operation-order.md) | 模拟器上线并报能力 |
| 7 | Recipe：物料、配方、发布（方案 A） | [modules/recipe](modules/recipe.md) | 后台能配「80℃ 投 1 包」 |
| 8 | Inventory：耗材、放置 | [modules/inventory](modules/inventory.md) | 茶包绑到 S3 |
| 9 | Cooking：校验、状态机、下发 | [modules/cooking](modules/cooking.md)、[protocol/operation-order](protocol/operation-order.md) | 手选配方 → MQTT → ACK → 完成 |
| 10 | 缺料 / 离线 / 乱序 | 同上 + [protocol/mqtt](protocol/mqtt.md) | Failed 且不重复投放；旧 epoch 被拒 |
| 11 | AfterSales | [modules/aftersales](modules/aftersales.md) | 维修中 SN 不能再绑定 |
| 12 | Catalog 轻量 | [modules/catalog](modules/catalog.md) | 后台维护，小程序只读 |
| 13 | `ITelemetryStore` + `dev_telemetry` | [protocol/telemetry](protocol/telemetry.md) | 影子能落水温/状态点；console 能按时间查 |

**本版不做：** AI、支付订单、组合料盒、推送中台、称重闭环、真机联调、TDengine 集群、EMQX 集群。

做到第 9 步，主链路就算通。11–13 可与主链路收尾并行，但 13 的接口要在 Device 骨架里先留着（第 5 步即可先放空实现）。
